# Amnezia Control 0.3.2

Панель, которая устанавливает WireGuard и AmneziaWG на том же VPS и управляет локальными клиентами. Интерфейс на русском и английском. Это исходный проект для собственного GitHub-репозитория `dagmagnat/amnezia-control`.

## Интерфейс 0.3.2

Импорт расположен по центру рабочей области, карточка занимает высоту по содержимому. Окно браузера и общая область настроек не прокручиваются: прокрутка остаётся внутри отдельных карточек. На узком экране настройки переключаются между «VPN и аккаунт» и «Адрес и копии»; обе формы сохраняют введённые поля при переключении. На 320×568 начальная форма импорта с кнопкой проверки помещается целиком.

## Исправление 0.3.1

Установка и обновление ожидают готовности HTTP-панели через общий `scripts/wait-panel.sh`. Промежуточные отказы соединения во время запуска больше не печатаются как ошибки. После готовности выводится «Панель готова / Panel is ready». Если все попытки исчерпаны, выводится диагностика, скрипт завершается с ошибкой, а обновление запускает откат. Проверка не перезапускает VPN.

## Что нового в 0.3.0

- Импорт `.conf`, ZIP и TAR.GZ: предварительная проверка, выбор одного серверного подключения из архива, перенос исходных ключей и массовое добавление клиентов.
- Чтение имён и приватных ключей из комментариев AntiZapret `# Client` / `# PrivateKey`; проверка соответствия приватного и публичного ключей.
- Повторный импорт пропускает существующих клиентов; клиентский `.conf` может дополнить запись, у которой нет приватного ключа. Существующие лимиты и учтённый трафик сохраняются.
- Снимок SQLite перед применением; откат при ошибке VPN. Проверка файлов и состояния между предварительным просмотром и применением.
- Обновлённый дизайн: более крупные надписи, компактный обзор, мобильное выдвижное меню и формы с дополнительными полями в раскрывающемся блоке.


## Что изменилось по сравнению с первоначальным макетом

Удалены demo-вход, вымышленные клиенты, имя «Алексей», трафик, локация и история. Показатели берутся из SQLite и `wg/awg`. Клиенты создаются с настоящими ключами; при ошибке движка запрос завершается ошибкой, а база откатывается. Секретные ключи не возвращаются в списках клиентов.

Работают создание/редактирование клиентов, описание, имя до 30 символов, последовательные `User 01`, `User 02`, массовое создание, `.conf`, QR, отключение/возобновление, удаление, лимит трафика, срок действия, импорт совместимого клиентского `.conf`, изменение endpoint, журнал событий, смена пароля, смена языка и скачивание резервной копии базы.

Основной экран рассчитан на высоту браузера, основной шрифт 16 px. Прокручиваются списки и длинные формы. На телефоне используется компактное выдвижное меню и карточки клиентов. Длинные списки, QR и раскрытые расширенные формы при необходимости прокручиваются внутри рабочей области.

## Требования

- Чистый Ubuntu 22.04/24.04/26.04 или Debian 12/13, systemd, root, TUN `/dev/net/tun`.
- x86_64 или ARM64. Рекомендуется от 2 ГБ RAM для сборки AmneziaWG Go; нужны сеть и свободное место для Go/toolchain.
- IPv4 и возможность открыть UDP-порты у провайдера. Полноценная IPv6-маршрутизация в этой версии не настраивается.
- Для стандартного WireGuard нужен поддерживаемый модуль ядра. Установка прекращается при ошибке модуля или запуска.

## Установка

Сначала загрузите **содержимое архива** в корень репозитория GitHub, а не один ZIP-файл. После публикации обновлённого кода на чистом VPS:

```bash
curl -fsSL https://raw.githubusercontent.com/dagmagnat/amnezia-control/main/scripts/install.sh -o /tmp/ac-install.sh
sed -i 's/\r$//' /tmp/ac-install.sh
sudo bash /tmp/ac-install.sh
```

Установщик предлагает `1) Русский (Russian)` или `2) English (Английский)`, запрашивает администратора и повтор пароля, порт панели, IP/домен. Выбирать один VPN при установке не нужно: устанавливаются оба движка и создаются два профиля.

По умолчанию:

- панель: `http://IP:8080` или `http://domain:8080`;
- WireGuard: `51820/udp`;
- AmneziaWG 3.1: `51821/udp`;
- backend доступен только локально на `127.0.0.1:8090`.

Установка из распакованного архива:

```bash
sudo bash ./scripts/install.sh --source "$(pwd)"
```

Само наличие открытой страницы не означает успешного VPN. Проверьте handshake клиента и доступ в Интернет.

## Источники VPN

WireGuard устанавливается из пакетов ОС. AmneziaWG Go и tools собираются из официальных репозиториев:

- https://github.com/amnezia-vpn/amneziawg-go
- https://github.com/amnezia-vpn/amneziawg-tools
- https://docs.amnezia.org/documentation/amnezia-wg/

Go загружается с `go.dev`; SHA256 сверяется с метаданными официального выпуска. Полные ревизии AmneziaWG записываются в `/etc/amnezia-control/engine-sources.txt`. По умолчанию берётся текущая ветка master upstream; для контролируемой сборки задайте `AWG_GO_REF` и `AWG_TOOLS_REF` через `sudo --preserve-env=AWG_GO_REF,AWG_TOOLS_REF`.

Новые AmneziaWG-интерфейсы используют официальный userspace-движок через `ac-awg@.service`. Старый `awg0` при обновлении сохраняет свой прежний сервис. Kernel-модуль AmneziaWG не требуется для новых профилей.

## Создание подключения

1. Нажмите «Создать клиента» и выберите WireGuard либо AmneziaWG. Для AmneziaWG доступны все поколения: 1.0, 1.5, 2.0, 3.0, 3.1.
2. Выберите количество. Имя можно оставить пустым для `User 01`, `User 02` и далее. Подсеть, UDP-порт, ключи сервера и параметры создаются автоматически, если подходящего подключения ещё нет. Для последующих клиентов той же версии подключение используется повторно. Обычный WireGuard не подменяет AmneziaWG при ошибке.
3. «Описание, трафик и срок» — свёрнутый раздел необязательных настроек. После создания нажмите имя клиента для редактирования или скачайте `.conf`/QR.
4. Панель покажет порт созданного подключения. Откройте его в firewall провайдера. Настройка NAT/forwarding и правил локального firewall выполняется проектом. Чужие правила не очищаются.

Параметры AmneziaWG автоматически генерируются для выбранного поколения, показываются в профиле и включаются в клиентские файлы. Дополнительные поля зависят от поколения. Изменение общих параметров существующего профиля требует подтверждения и перевыпуска всех его клиентских конфигураций. Возможность применения окончательно проверяет установленный движок: при несовместимости профиль не выдаётся за успешно созданный.

Версий 2.1/2.5 в проекте нет. Название профиля `legacy` после обновления означает старую конфигурацию без параметров обфускации — это не 3.1, несмотря на подпись в первоначальном макете.

## Лимиты и срок

Лимит — суммарный объём RX + TX в байтах с момента включения учёта, не месячная подписка. Интерфейс позволяет указать ГиБ, изменить лимит и обнулить расход. Учёт хранится в базе и учитывает сброс счётчиков движка. Проверка срока и квоты выполняется каждые 10 секунд, поэтому возможно небольшое превышение до следующей проверки. Если сервер аварийно выключен между проверками, последние секунды трафика могут не попасть в базу.

При истечении срока/квоты peer исключается из рабочей конфигурации. Продление срока или увеличение квоты возвращает доступ при включённом клиенте. «Онлайн» — handshake не старше трёх минут; «Доступ разрешён» не означает, что устройство сейчас подключено.

## Обновление уже установленного проекта

Не запускайте установщик заново и не удаляйте конфигурации. После загрузки версии 0.3.2 в GitHub скачайте **новый** updater отдельно, чтобы не выполнить старый файл с CRLF:

```bash
curl -fsSL https://raw.githubusercontent.com/dagmagnat/amnezia-control/main/scripts/update.sh -o /tmp/ac-update.sh
sed -i 's/\r$//' /tmp/ac-update.sh
sudo bash /tmp/ac-update.sh
```

Updater клонирует релиз во временную папку; `git pull` поверх локальных исправлений не используется. До изменения сохраняются код, база и конфигурации в `/root/amnezia-control-backups/ДАТА/`. При ошибке запуска выполняется восстановление предыдущих кода и данных. Настройки Nginx (ваш IP:порт) и серверные ключи сохраняются. Пакеты, установленные в ходе обновления, автоматически не откатываются.

Из локальной распакованной версии:

```bash
sudo bash ./scripts/update.sh --source "$(pwd)"
```

Обновление добавляет поля в старую SQLite, принимает существующий `awg0/wg0`, сохраняет серверную пару ключей и клиентов. Для старых peer без сохранённого приватного ключа новое скачивание невозможно: продолжайте использовать исходный клиентский файл или импортируйте его. Если серверная конфигурация отсутствует, автоматическое принятие интерфейса невозможно — сохраните данные и проверьте журнал.

После обновления:

```bash
sudo bash /opt/amnezia-control/scripts/status.sh
```

В браузере нажмите Ctrl+F5. Версия `0.3.2` видна над заголовком.

## IP, домен и порт

Адрес панели меняется в «Настройки» или командой:

```bash
sudo bash /opt/amnezia-control/scripts/panel-address.sh
```

Домен задаётся без `http://` и без порта. Проверяются значения и Nginx; предыдущая конфигурация сохраняется в `.before-change`. Новый TCP-порт нужно открыть у провайдера и, если используется, в UFW. IP-вход остаётся доступен. Порт 8090 зарезервирован для backend.

HTTP-доступ передаёт пароль без TLS. Для постоянного использования подключите домен и HTTPS:

```bash
sudo bash /opt/amnezia-control/scripts/https.sh
```

Для Certbot нужны корректная DNS-запись и доступность стандартных портов 80/443. Сертификат для IP автоматически не выпускается. При существующей HTTPS-конфигурации форма смены адреса её не перезаписывает; изменения выполняйте на VPS с проверкой сертификата.

## Relay и резервный сервер

VPN endpoint профиля — `IP:порт` или `домен:порт`, включая IDN/.рф. Это отдельная настройка от адреса web-панели. Relay должен передавать UDP к соответствующему порту origin и корректно возвращать ответный трафик (DNAT + обратный маршрут/SNAT либо UDP relay). HTTP reverse proxy вместо UDP relay не подходит.

Смена DNS не гарантирует немедленного переключения уже работающих WireGuard-клиентов: некоторым потребуется переподключение. Автоматического failover/DNS-управления нет. Резервный VPS устанавливается отдельно и переключается вручную; общий домен не заменяет перенос серверной идентичности, peer и параметров обфускации.

## Импорт и AntiZapret

В разделе «Импорт» есть два режима:

1. **С другого сервера.** Выберите исходный серверный `.conf` или архив `.tar.gz` / `.zip`. Можно добавить клиентские `.conf` одновременно. Укажите внешний VPN endpoint `домен:порт` либо `IP:порт`. Если архив содержит несколько серверов, выберите один и нажмите «Проверить файлы» повторно. Например, `wireguard/vpn.conf` и `wireguard/antizapret.conf` из AntiZapret переносятся по отдельности.
2. **В имеющееся подключение.** Выберите профиль и один или несколько клиентских `.conf` с его оригинальным серверным PublicKey. Поддерживается дополнение уже принятого peer: приватный ключ восстанавливается из клиентского файла без создания дубликата.

Проверка не меняет базу или VPN. План показывает число новых, дополненных и уже существующих клиентов, ошибки и ограничения. Только кнопка «Перенести подключения» применяет план. Если файлы или записи VPN изменились, потребуется повторная проверка. Данные архива обрабатываются в памяти; скрипты, hooks и файлы базы AdminPanelAZ не выполняются. Из архива берутся только конфигурации `.conf`; символические ссылки и небезопасные пути отвергаются. Ограничения: 8 МиБ загрузки, 24 МиБ распакованных данных и 4096 элементов.

Импорт сохраняет серверный PrivateKey, PublicKey и исходные параметры AmneziaWG, клиентские ключи, PSK и IPv4-адреса. Общие поля обфускации сверяются с сервером; клиентские Junk/CPS могут отличаться. Если приложен оригинальный клиентский `.conf`, сохраняются его DNS, MTU, AllowedIPs, keepalive и префикс Address. Поддержаны индивидуальные IPv4 `/32` peers в одной частной серверной подсети `/16`–`/30`. Site-to-site маршруты, несколько адресов интерфейса и IPv6 миграция требуют отдельной доработки и отклоняются до применения.

AntiZapret может хранить имя и приватный ключ клиента в комментариях серверной конфигурации. Они распознаются, и соответствие ключей проверяется официальной командой `wg pubkey` / `awg pubkey`. Если приватного ключа нет, существующий клиент сохраняет доступ, но QR/скачивание недоступны до предоставления его `.conf`. Если ключ есть, а клиентского файла нет, скачиваемый файл создаётся со стандартными DNS/маршрутами; **это не копия исходных клиентских настроек**.

Старые конфигурации AmneziaWG AntiZapret с `S1=S2=0` и стандартными `H1..H4=1,2,3,4` могут работать с обычным сервером WireGuard. Импорт распознаёт только этот режим совместимости и сохраняет Junk/CPS из исходного клиентского файла. Современная обфускация AmneziaWG не преобразуется в WireGuard. Выбор версии при создании нового клиента остаётся отдельным действием: импорт не обновляет протокол старых устройств до 3.1.

**Перед переключением старых устройств проверьте внешний UDP-порт, DNS и маршруты.** Например, AntiZapret может принимать AmneziaWG на одном внешнем порту и перенаправлять на другой внутренний порт WireGuard. Такие relay/DNAT правила, выборочная маршрутизация AntiZapret, Knot Resolver, OpenVPN и пользовательские скрипты этой панелью не восстанавливаются. Клиентский `.conf` нужен для точной проверки. Один архив базы AdminPanelAZ без VPN-конфигураций недостаточен. Конфликт порта, адреса, ключей или параметров останавливает импорт; исходные работающие подключения не перезаписываются.

Перед применением сохраняется согласованный снимок базы в `/var/lib/amnezia-control/import-backups/`. Он содержит приватные ключи и доступен только root. Путь к снимку показывается после успешного переноса. Для полной резервной копии файлов воспользуйтесь `scripts/backup.sh`.

### Где взять старые клиентские конфигурации

На **старом сервере AntiZapret**, с которого переносите пользователей, файлы обычно находятся здесь:

- `/root/antizapret/client/amneziawg/vpn/` — AmneziaWG с полным VPN-маршрутом.
- `/root/antizapret/client/amneziawg/antizapret/` — AmneziaWG с выборочной маршрутизацией AntiZapret.
- `/root/antizapret/client/wireguard/` — варианты для обычного WireGuard.

Проверить наличие файлов без вывода ключей:

```bash
sudo find /root/antizapret/client/amneziawg -type f -name '*.conf'
```

Собрать обе папки AmneziaWG в архив:

```bash
sudo bash -ec 'umask 077; tar -czf /root/amnezia-clients.tar.gz -C /root/antizapret/client amneziawg; chmod 600 /root/amnezia-clients.tar.gz'
```

Скачайте `/root/amnezia-clients.tar.gz` со старого VPS через SFTP. Этот архив содержит приватные ключи и предназначен для личного переноса, а не публичного репозитория. Серверная резервная копия и клиентские файлы дополняют друг друга: из клиентских файлов берутся точные Endpoint, DNS, маршруты и параметры AmneziaWG.

Форматы проверены по исходному коду [AntiZapret client.sh](https://github.com/GubernievS/AntiZapret-VPN/blob/main/setup/root/antizapret/client.sh) и [AdminPanelAZ backup manager](https://github.com/Kirito0098/AdminPanelAZ/blob/main/backend/app/services/backup_manager.py). Не загружайте приватные архивы и `.conf` в публичный GitHub.

## Резервная копия и восстановление

«Сохранить подключения» — резервная копия настроек и ключей. Она нужна для восстановления при сбое или переносе. Создавать новую конфигурацию через этот раздел не нужно. В панели доступна SQL-копия базы. Полная копия файлов и согласованный снимок SQLite:

```bash
sudo bash /opt/amnezia-control/scripts/backup.sh /root/amnezia-control-backup.tar.gz
```

SQL-копию можно восстановить из доверенного локального файла:

```bash
sudo /opt/amnezia-control/.venv/bin/python /opt/amnezia-control/backend/manage.py restore
sudo /opt/amnezia-control/.venv/bin/python /opt/amnezia-control/backend/manage.py reconcile
```

Перед восстановлением инструмент сохраняет предыдущую базу в `.before-restore`. После полного переноса на другой VPS проверьте IP/домен, наличие интерфейсов и UDP-портов; восстановление файлов само по себе не настраивает firewall провайдера. Копии содержат приватные ключи.

## Пароль и удаление

Сброс пароля через SSH:

```bash
sudo bash /opt/amnezia-control/scripts/reset-password.sh
```

Удаление:

```bash
sudo bash /opt/amnezia-control/scripts/uninstall.sh
```

Выбор: только панель либо панель вместе с её управляемыми VPN. Требуется ввод `REMOVE`; перед удалением создаётся копия. Ранее принятые `wg0/awg0`, общие системные пакеты и `/root`-копии сохраняются: установщик не считает их собственностью проекта. Forwarding не отключается глобально, чтобы не повредить чужие сервисы.

Для 0.3.0 пройдены 15 регрессионных тестов API и 11 тестов миграции: сохранение ключей/настроек, повторный импорт, дополнение peer, откат, изменившийся план, небезопасные пути и ограничение распаковки. Предоставленный архив AntiZapret проверен локально: два подключения по 156 клиентов, все 312 пар ключей подтверждены X25519, пробный импорт и повторный пропуск записей прошли без конфликтов. Приватные данные архива в поставку не включены. Реальная миграция этих устройств на VPS ещё требует сверки исходного клиентского `.conf`, DNS и UDP-портов.

Через встроенный браузер проверены предварительный просмотр и применение синтетического архива, desktop 1366×768, mobile 390×844 и 320×568. На 320×568 основное меню, создание и редактирование клиента помещаются без прокрутки; расширенные формы и длинные списки могут требовать внутреннюю прокрутку. Снимки интерфейса сделаны с изолированной тестовой базой.

В предыдущем выпуске 0.2.2 на тестовом VPS Ubuntu 24.04 проверены реальные handshake и ICMP через NAT для WireGuard и AmneziaWG 1.0/1.5/2.0/3.0/3.1 в отдельном network namespace. Пользователь затем подтвердил внешнее подключение AmneziaWG 3.1 на Windows. Чистая установка ОС с нуля, реальные Android/iOS-устройства и перенос всех архивных клиентов этой проверкой не покрываются.

`tests/linux-smoke.sh` — дополнительная ручная проверка профилей на тестовом VPS после установки. Она создаёт и удаляет временные интерфейсы, требует root и явного `AC_RUN_VPN_SMOKE=1`.

Проект не подключает чужие VPN по удалённому API. Локальные HTTP endpoints служат связи браузера с панелью на этом же VPS. Нет вымышленных клиентов, тестовых паролей и демонстрационного режима в поставке.
